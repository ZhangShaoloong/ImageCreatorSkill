# 设计文档：image-creator 交互式参数向导

- **日期**: 2026-10-01
- **状态**: 待实现
- **范围**: 仅修改 `SKILL.md`（+ 可选的 README 文档同步）。**不改** `image-generator.js` 的运行逻辑。

## 背景与动机

当前 `image-creator` skill 的用法是"一次性把所有参数放在一条指令里"：

```
/image 一只橘猫 --style cartoon-2d --aspect 9:16 --multi-angle 3
```

对普通用户来说门槛偏高——记不全参数名、拼错 flag、不确定哪个是默认。目标是把**首次/常规使用**的体验改成：用户只需口述画面（场景描述），其余参数由 Claude 用带按钮的 `AskUserQuestion` 逐步引导录入，每个问题都可接受默认值或一键跳过。

## 关键认知

"交互式"是 **Claude 与用户之间的对话行为**，不是 JS 脚本的行为。`image-generator.js` 保持纯函数角色：吃 `prompt + options`，调用真实 API（`https://api.agnes-ai.cn/v1/images/generations`），保存本地图，退出。它无法在中途停下"问你"。

因此本设计**只在 `SKILL.md` 增加一段"交互向导"指令脚本**，让 Claude 在触发 skill 后先问、再调 JS。JS 侧唯一需要的改动是：把 `--model` flag 真正接进 `callApi`（见 §实现要点·JS 微改），让向导里选的模型能落到 API 请求。

## 交互模式判定（双模式）

SKILL.md 里明确两种入口，Claude 按下述规则分流：

| 用户输入形态 | 走的路径 |
|---|---|
| 指令里已带**任意 flag**（`--style`、`--aspect`、`--multi-angle` 等）| **快速路径**：不弹向导，未给的值用默认，直接生成 |
| 只有**场景描述、无任何 flag**，或**空的 `/image`** | **交互向导**：先补描述（若空）→ 逐问参数 → 确认 → 生成 |

判定口诀：**"有 flag = 快速，无 flag = 向导"**。这样老用法不坏，新交互是默认体验。

## 交互向导流程

顺序已定（风格优先）。全用 `AskUserQuestion` 按钮，每问含"接受默认"与"直接生成/跳过"出口。

### 第 0 步：场景描述（自由输入，非按钮）
- 若用户进来时已给了描述 → 直接进第 1 问。
- 若 `/image` 为空 → 先问："请描述你想生成的画面（自由打字，例：`一个现代风格的别墅，绿树环绕`）"。
- 描述作为 API 的 `prompt`，并写入文件名。

### 第 1 问：风格
- 选项：`photorealistic（默认）` / `cartoon-2d` / `cartoon-3d`
- 默认：photorealistic

### 第 2 问：比例 / 尺寸
- 选项：`16:9（默认）` / `4:3` / `1:1` / `9:16` / `自定义 w×h`
- 默认：16:9（1920×1080）
- 选"自定义"时追问 width / height（合法范围 256–8192）

### 第 3 问：手部 / 手指
- 选项：`显示（默认）` / `不显示` / `增强手指细节`
- 默认：显示（标准细节）

### 第 4 问：多角度
- 选项：`单角度（默认）` / `多角度 N 个`
- 默认：1
- 选"多角度"时追问 N（≥1）

### 第 5 问：模型
- 选项：`agnes-image-2.1-flash（默认）` / `agnes-image-2.5-flash` / `其他`
- 默认：agnes-image-2.1-flash
- （可用模型列表来自 `/v1/models`，含 2.1 与 2.5 两个 image 模型；"其他"允许手填模型 ID）

### 第 6 问：确认
- 汇总全部参数展示，选项：`直接生成` / `改一项` / `取消`
- "改一项"→ 回到对应那问；"取消"→ 结束不生成。

### 快捷出口
- 每一问都带"接受默认"。
- 第 1 问前提供"跳过向导，全用默认直接生成"选项，满足老用户偷懒。

## 实现要点

### SKILL.md 改动
1. **新增章节** `## 交互式向导`：把上面第 0–6 问写成 Claude 要遵循的指令脚本（每问的文案、选项、默认、追问条件、快捷出口）。
2. **双模式判定**：在"Usage Patterns"处补一句规则——有 flag 走快速、无 flag 走向导。
3. **每问对应 JS flag 的映射表**：风格→`--style`、比例→`--aspect` 或 `--width/--height`、手部→`--no-hands`/`--fingers`、多角度→`--multi-angle N`、模型→`--model`。
4. 保留原"参数参考表""快速用法"等内容不动。

### JS 微改（`image-generator.js`）
- 给 `parseArgs` 增加 `--model` 解析（当前 DEFAULTS 有 model，但 CLI 没暴露该 flag），使向导选的模型能传入 `callApi`。
- 其余逻辑（真实 API、保存、文件名中文修复）已就绪，不改。

### 数据流
```
用户输入
  ├─ 有 flag → 快速路径 → generateImage(prompt, options) → 保存 → 返回路径
  └─ 无 flag → 交互向导（Claude 逐个 AskUserQuestion）
                  → 收集 {style, aspect/w/h, hands, multiAngle, model}
                  → 确认 → generateImage(prompt, options) → 保存 → 返回路径
```

## 错误处理
- 向导中任一问取消 → 不生成，明确告知"已取消"。
- 自定义 w/h 超范围 → 按 `validateParameters` 报错并让用户重输。
- 模型 ID 手填无效 → API 返回错误时透传，提示可用模型列表。
- API key 缺失 → 提示先跑 `/image-setup`（现有行为）。

## 验收标准
- [ ] 空 `/image` → 触发交互向导，逐问按钮，含默认与跳过出口。
- [ ] `/image 一只橘猫`（无 flag）→ 补描述已有 → 直接进向导。
- [ ] `/image 一只橘猫 --style cartoon-2d`（有 flag）→ 快速路径，不弹向导。
- [ ] 向导中选"多角度 N" → 生成 N 张。
- [ ] 向导中选模型 2.5 → API 请求体 model 为所选 ID。
- [ ] 确认页汇总值与用户所选一致。
- [ ] 老的一行式 flag 用法仍工作。

## 不做（YAGNI）
- 不做"记住上次参数"的偏好持久化。
- 不新增图像后处理/编辑。
- 不做向导的图形化 UI（按钮问答即足够）。
- 不改 JS 的真实 API 与保存核心逻辑（只加 `--model` flag）。

## 风险与取舍
- **按钮问答略重**：6 问可能显得啰嗦。缓解：默认全选 + "跳过向导直接生成"一键出口，让熟练用户 1 步走完。
- **双模式判定易误判**：只要"有 flag 就是快速"的硬规则写死在 SKILL.md，不留模糊地带。
